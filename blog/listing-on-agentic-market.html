Как залистить агента на agentic.market (и почему «просто 402» недостаточно)

2026-07-28 · 3 мин чтения

Agentic.Market — не форма «заполни и жди модерацию». Это витрина поверх CDP Bazaar: каталог Coinbase, который индексирует эндпоинты автоматически, когда через их фасилитатор проходит реальный settle.

Отсюда жёсткое правило, которое ломает половину попыток: пока платёж не прошёл settle через CDP Facilitator, тебя в каталоге нет. Открытый фасилитатор вроде facilitator.xpay.sh может принимать оплату у живых клиентов — но в agentic.market он тебя не занесёт. Это не баг. Так устроен discovery-слой Coinbase.

Как устроен листинг на самом деле

Ты отдаёшь HTTP 402 с x402 v2 и блоком extensions.bazaar (описание, input/output, schema). Клиент (awal, агент, твой тестовый кошелёк) присылает PAYMENT-SIGNATURE. Твой сервер гонит payload на verify → settle фасилитатора.

Если settle прошёл через CDP (https://api.cdp.coinbase.com/platform/v2/x402) и в payload есть paymentPayload.resource, CDP вытаскивает bazaar-метаданные и кладёт ресурс в индекс. Agentic.Market читает этот индекс. Отдельной регистрации нет.

Официально: indexing runs after settle completes; verify alone is not enough. И ещё: ресурсы без активности 30 дней выпадают из выдачи. Один «пробный» settle — это вход. Дальше нужна живая активность.

Чеклист до первого settle

Транспорт

  • Публичный HTTPS URL (не localhost, не http).
  • Эндпоинт отвечает на незаплаченный запрос именно 402, не 200 и не 405.
  • Лучше сразу POST + GET на один путь: сканеры Bazaar и разные клиенты ходят разными методами. Один метод → часто 405 → «No x402 Setup Detected».

Платёжный конфиг

  • x402Version: 2
  • scheme: exact, сеть eip155:8453 (Base) или testnet
  • USDC asset, payTo — твой кошелёк
  • Цена ≥ $0.001 USDC
  • maxTimeoutSeconds задан
  • В accepts есть корректный extra (name/version для USDC)

Bazaar extension

  • Блок extensions.bazaar с info.input / info.output / schema
  • Input проходит JSON Schema validation
  • В settle-запросе обязательно paymentPayload.resource (URL ресурса) — без него CDP не знает, что индексировать

Фасилитатор

Для листинга на agentic.market — только CDP:

  • URL: https://api.cdp.coinbase.com/platform/v2/x402
  • Нужны CDP API Key ID + Secret (JWT-авторизация на verify/settle)
  • Free tier: 1000 транзакций/мес, дальше ~$0.001 за tx

facilitator.xpay.sh и другие open-фасилитаторы: оплата у клиентов может работать, каталог Coinbase их не видит.

Перед живыми деньгами имеет смысл прогнать официальный validate: POST https://api.cdp.coinbase.com/platform/v2/x402/validate — проверка 402 и bazaar-блока без реального платежа.

Пошагово: от кода до появления в каталоге

1. Собери агента
Логика → цена → кошелёк → генератор (с включённым Bazaar и, желательно, POST+GET). Resource URL = тот HTTPS, который будет в проде.

2. Задеплой
Render, Fly, VPS, Cloudflare Tunnel — не важно. Важно: снаружи стабильный HTTPS и 402 без авторизации «до» x402.

3. Подключи CDP Facilitator
В портале Coinbase Developer Platform создай API key. В сервере укажи CDP URL и подпись запросов к /verify и /settle через CDP credentials. Пока settle идёт на xpay.sh — agentic.market тебя не увидит, даже если 402 идеальный.

4. Сделай первый реальный settle

npx awal x402 pay https://твой-https-url/ \
  -X POST \
  -d '{"symbol":"BTC"}' \
  -q '{"symbol":"BTC"}'

Должен быть 200 и ончейн-перевод USDC на твой payTo. Именно этот settle CDP использует для индексации.

5. Проверь индекс

# Discovery API
GET https://api.cdp.coinbase.com/platform/v2/x402/discovery/resources
# или search по твоему домену/описанию

Витрина: agentic.market. Индексация асинхронная: не всегда «через 10 секунд». Если settle успешен, а в каталоге пусто — проверь paymentPayload.resource, bazaar schema и что settle точно ушёл в CDP, а не в другой фасилитатор.

6. Не дай себе умереть в 30-дневном окне
После первого settle нужны повторные оплаты. Иначе ресурс выпадет из выдачи. Для старта достаточно редких своих же тестовых вызовов; для роста — реальный спрос агентов.

Типичные причины «No x402 Setup Detected»

Симптом Что обычно не так
405 вместо 402 Зарегистрирован только POST, сканер бьёт GET (или наоборот)
200 без оплаты x402 middleware не стоит / стоит после другой логики
402 есть, в каталоге нет Settle через xpay/другой фасилитатор, не CDP
Settle ок, всё равно нет Нет paymentPayload.resource или сломан extensions.bazaar
Был в каталоге, пропал Нет активности 30+ дней
Не проходит оплата на CDP Нет/неверные CDP API keys, не тот network/asset

Два режима одной кассы

Режим A — жить и принимать деньги
Можно на open-фасилитаторе (xpay и др.): клиенты платят, USDC приходит, API работает. Листинга в agentic.market нет.

Режим B — быть в agentic.market
Нужен CDP Facilitator + ключи + хотя бы один успешный settle через CDP + bazaar extension. После этого агенты находят тебя через каталог Coinbase / agentic.market / awal bazaar search.

Многие делают гибрид: сначала поднимают кассу на open-фасилитаторе, проверяют логику и оплату, потом переключают verify/settle на CDP, когда готовы к листингу. Главное — не ждать, что «раз 402 красивый — значит я уже в маркете». Маркет смотрит не на красоту заголовка, а на settle в своём фасилитаторе.

Короткий итог

  • Сделай честный 402 + bazaar metadata + HTTPS + оба метода.
  • Для agentic.market переведи settle на CDP Facilitator (нужны API keys Coinbase).
  • Проведи один успешный settle с paymentPayload.resource.
  • Проверь discovery API и витрину.
  • Не бросай эндпоинт: 30 дней тишины = вылет из индекса.

Agentic.Market не «одобряет» тебя руками. Он подхватывает тех, через кого уже прошли реальные платежи в инфраструктуре Coinbase. Если платежи идут мимо CDP — ты продаёшь втихую. Если settle идёт через CDP — ты в витрине, где агенты ищут, что купить следующим вызовом.
